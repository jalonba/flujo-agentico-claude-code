# HU-03 · Reservar una cita

**Estado:** Hecha · **Tamaño:** M · **Capa:** dominio + escritura en `localStorage` + UI · **Depende de:** HU-02
**Verificación:** [VER-03](../../docs/verificaciones/VER-03.md)

## Historia

Como **persona que quiere agendar**, quiero **reservar un horario libre con mi nombre**, para
**asegurar mi cita sin chocar con la de otra persona**.

## Contrato de dominio

```ts
reservarCita({ citas, solicitud: { nombre, fecha, inicio }, config, ahora })
  // → { ok: true, cita: Cita, citas: Cita[] }
  // → { ok: false, error: "NOMBRE_INVALIDO" | "HORARIO_INVALIDO" | "HORARIO_PASADO" | "HORARIO_OCUPADO" }
```

Orden de validación: nombre → horario en la grilla → ya empezó → ocupado.

## Criterios de aceptación

| Id | Dado | Cuando | Entonces |
|---|---|---|---|
| HU-03.c1 | un horario libre y un nombre | pulso **Reservar** | la cita se guarda en `localStorage`, aparece «Cita reservada: {nombre}, {fecha} a las {inicio}.» (`role="status"`) y el bloque pasa a «Ocupado» |
| HU-03.c2 | una cita existente que se solapa con el horario pedido (incluso si la guardó otra pestaña después de pintar la lista) | pido reservar | se rechaza con `HORARIO_OCUPADO` («Ese horario acaba de ocuparse. Elige otro.») y no se guarda nada |
| HU-03.c3 | un horario cuyo inicio es ≤ `ahora`, o una fecha pasada | pido reservar | se rechaza con `HORARIO_PASADO` («Ese horario ya pasó. Elige uno más tarde.») y no se guarda nada |
| HU-03.c4 | un nombre vacío, solo espacios o de más de 80 caracteres | pido reservar | se rechaza con `NOMBRE_INVALIDO`, el campo queda con `aria-invalid="true"` y el mensaje asociado; no se guarda nada |
| HU-03.c5 | un `inicio` que no está en la grilla del día (p. ej. `08:10` o `16:45` con cierre 17:00) | pido reservar | se rechaza con `HORARIO_INVALIDO` |
| HU-03.c6 | una cita reservada | recargo la página | la cita sigue ahí y su bloque sigue «Ocupado» |
| HU-03.c7 | — | siempre | `reservarCita` no muta la lista recibida; reservar uno tras otro todos los bloques de un día produce citas que nunca se solapan entre sí |

## Reglas de negocio

- `nombre` se guarda recortado (sin espacios al inicio ni al final).
- `nombre` válido: 1–80 caracteres **visibles** (grafemas, no unidades UTF-16), sin caracteres de
  control ni invisibles, y con al menos una letra o número (decisión tomada en VER-03).
- Una cita guardada con `fin ≤ inicio` es dato corrupto (VER-03).
- La agenda se vuelve a pintar cada minuto y tras un rechazo, para no ofrecer bloques que ya empezaron.
- `id = "{fecha}T{inicio}"`, `fin = inicio + duracionMin`.
- La UI vuelve a leer `localStorage` justo antes de reservar, para no confiar en una lista vieja.

## Datos que toca

Lectura y escritura de `localStorage["agenda-citas:v1"]`.

## Fuera de alcance

Cancelar o editar citas, confirmación por correo, varias agendas.
